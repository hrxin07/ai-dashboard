# 实施计划：人工智能专业的职业生涯规划学习实践工作台

- **依据文档**：[需求文档](../需求文档.md)
- **计划版本**：V1.0
- **日期**：2026-10-07
- **任务索引**：[docs/tasks/README.md](./tasks/README.md)

## 1. 目标与范围

以 Next.js App Router、TypeScript、Tailwind CSS、MySQL/MariaDB、Prisma 和 JWT 实现面向人工智能专业学生的职业生涯规划学习实践工作台。MVP 覆盖注册登录、JWT 鉴权、个人资料、职业规划、职业方向、学习实践任务、工作台统计和规则推荐；管理员、PDF 导出、大模型接入等内容不纳入本期。

## 2. 架构决策

- **应用形态**：使用 Next.js App Router；页面放在 `app/`，后端接口使用 `app/api/**/route.ts` 的 Route Handlers。
- **数据访问**：Prisma 7 作为唯一数据库访问层，通过 MariaDB driver adapter 连接 MySQL/MariaDB。`CareerPath` 通过 seed 脚本写入不少于 6 条公共数据。
- **生产部署**：提供 Dockerfile 与服务器端 Docker Compose 配置；业务数据由外部 MySQL/MariaDB 持久化，`DATABASE_URL`、`SHADOW_DATABASE_URL` 和 `JWT_SECRET` 由部署环境注入；ai-dashboard 本地、容器和宿主机统一使用 `3001` 端口。
- **认证**：用户名/邮箱与密码登录；密码用 bcryptjs 哈希；登录后把 JWT 放入 `HttpOnly` Cookie。受保护 Route Handler 必须验证用户身份并以 JWT 中的用户 ID 限定查询范围。
- **输入校验与返回格式**：Zod 校验所有写入 API；接口统一返回 `{ success, message, data }`。客户端只负责体验校验，服务端校验为最终依据。
- **页面访问保护**：通过 `middleware.ts` 拦截受保护页面；接口内部仍要再次鉴权，避免仅依赖前端路由保护。
- **受保护页面渲染**：读取登录 Cookie 的布局和页面采用普通动态服务端渲染，不启用 Cache Components 与 Partial Prefetching，避免预渲染阶段读取会话数据导致运行时错误。
- **UI 原则**：深蓝、紫色、青色的轻量科技感视觉，桌面优先且响应式；优先清晰的空状态、错误反馈与可演示闭环，而非复杂动效。

## 4. 实施阶段

### 阶段一：基础与认证
完成可运行的 Next.js 项目、MySQL/MariaDB + Prisma 接入、注册登录及 JWT 保护。该阶段完成后，用户可创建账户、登录、退出，并不能越权读取数据。

- 任务 1：项目脚手架与开发规范
- 任务 2：Prisma、MySQL/MariaDB 与基础数据模型
- 任务 3：用户注册闭环
- 任务 4：登录、JWT 与受保护访问
- 任务 5：应用壳、当前用户和退出登录

### 阶段二：个人规划闭环
完成资料和职业规划功能，用户可以维护职业目标和学习基础。

- 任务 6：个人资料 API 与页面
- 任务 7：职业规划 API
- 任务 8：职业规划页面

### 阶段三：职业探索与学习实践
完成职业方向公共数据、学习实践任务的增删改查与筛选。

- 任务 9：职业方向种子数据与展示
- 任务 10：学习实践任务 API
- 任务 11：学习实践任务页面

### 阶段四：工作台、推荐与交付
汇总用户数据、输出推荐结果，完善质量检查与使用文档。

- 任务 12：工作台统计与概览页面
- 任务 13：规则职业推荐 API 与页面
- 任务 14：响应式优化、异常状态与交付文档

## 5. 检查点

- **基础与认证检查点（任务 1–5 后）**：项目可构建；MySQL/MariaDB 迁移可执行；可完成“注册 → 登录 → 受保护页面 → 退出”闭环。
- **个人规划检查点（任务 6–8 后）**：登录用户可保存并再次读取自己的资料和规划；跨用户访问必须被拒绝或无数据返回。
- **学习实践检查点（任务 9–11 后）**：职业方向至少 6 条；可完成“新增任务 → 筛选 → 更新状态 → 删除”的闭环。
- **交付检查点（任务 12–14 后）**：仪表盘和推荐有效；静态检查、生产构建均通过；README 可让他人独立运行项目。Docker 镜像构建与容器启动验证需在具备 Docker 环境后完成。

## 6. 风险与缓解措施

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| MySQL/MariaDB 未启动、连接配置错误或业务库与 shadow database 相同 | 高 | 在 `.env.example` 写明两个 URL 格式；最早执行 Prisma 迁移验证。 |
| JWT 只在前端校验 | 高 | 中间件只负责页面体验；每个受保护 API 通过统一服务端函数验证 JWT 与资源归属。 |
| Prisma/Next.js 版本兼容问题 | 中 | 统一锁定依赖版本，并在任务 2 后立即执行迁移和构建。 |
| 需求范围扩张为复杂 AI 能力 | 中 | MVP 使用关键词与权重规则；外部大模型仅作为后续扩展。 |
| 演示数据不足或空页面体验差 | 中 | 通过 CareerPath seed 数据、明确空状态和演示账号说明保障展示效果。 |

## 7. 待确认项

1. MySQL/MariaDB 的主机、端口、数据库名、账户信息由部署环境决定；业务库和 shadow database 必须不同，代码仅提供 `.env.example`，不得提交真实凭据。
2. 本期默认每名用户维护一份主职业规划；如后续需要多个历史版本，再单独扩展数据模型和页面。
3. 职业推荐采用中文关键词/权重规则，不调用外部 AI 模型或付费 API。
4. 若项目开始前已有 UI 设计稿、学校指定依赖版本或测试规范，应在任务 1 前合并进本计划。
